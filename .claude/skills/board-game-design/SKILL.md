# 桌遊設計準則(Board Game Design Principles)

本 skill 將大師級設計師的核心思想濃縮為:**七大原則**、**常見病灶診斷表**、**數值設計規範**、**審查清單**。
修改本專案(賽博貿易戰 2049)規則前,先讀 `RULES.md`、`config/rules.json`、記憶中的 v2 已確認語意(不可回退),再用本準則審查。

## 一、七大設計原則

### 1. 簡單規則,深度湧現(Reiner Knizia)
- 遊戲的魔力不在複雜,而在「簡單規則 × 玩家互動」湧現出的深度。每加一條規則都要問:**刪掉它遊戲會壞嗎?**
- 主題的目的不是擬真,而是**模擬該主題下的思考過程與情緒**(科技冷戰=軍備競賽的焦慮+盟友的猜忌)。
- **計分/勝利條件定義了整個遊戲**:玩家會直奔得分最快的路,所以先設計「你希望玩家做什麼」,再讓勝利條件獎勵那件事。
- 設計的生命線是「測試→修正」循環:早期大改、後期微調。改規則前先讓模擬器跑基準線。

### 2. 一連串有趣的決策(Sid Meier / Characteristics of Games)
- 每個回合玩家都該面對**至少一個非顯然的取捨**。若某選項永遠最優(或永遠不選),它就不是決策,是流程——刪掉或修費用。
- 決策密度 > 遊戲長度:回合裡沒有決策的步驟(自動收入、強制結算)應該自動化、壓縮、或合併。
- **啟發式風景(heuristic landscape)**:新手要有「看得懂的好策略」(蓋卡賺錢),老手要有「更深一層的反直覺策略」(故意示弱、養肥再偷)。兩層都要存在。

### 3. 順著人性設計(Mark Rosewater, 20 Years 20 Lessons)
- **改遊戲去配合玩家,不要改玩家來配合遊戲**:玩家一定會囤資源、一定會打領先者、一定會記仇——規則要讓這些本能行為本身就有趣。
- **美學與細節很重要**:卡名、梗、圖示是玩家與遊戲建立感情的入口(本專案的梗名是資產,別在重構中犧牲)。
- **「大家都喜歡但沒人熱愛」=失敗**:每個角色/陣營都要有讓某類玩家「就是要玩這個」的尖銳賣點,寧可極端不要平庸。
- **限制激發創造力**:設計卡死時,加一條限制(費用上限、區域限制)往往比加一個新系統更有效。
- 玩家幻想(player fantasy)優先:打台灣要有「造王者的權力感」、打牆國要有「逆襲追趕的爽感」、打米國要有「捍衛霸權的壓迫感」。每條規則都要服務該陣營的情緒。

### 4. 不對稱要共享文法(Volko Ruhnke COIN / Cole Wehrle Root)
- 真實衝突中各方**目標、手段、計量方式都不同**——不對稱陣營是現代設計的核心語言。
- 但不對稱必須建立在**共享文法**上:所有人用同一套行動/資源/地圖規則,差異放在「目標與加成」,否則教學成本爆炸。
- 不對稱遊戲的平衡靠**政治**而非數值:領先者要「看得見」,讓其他玩家有動機與工具聯合制衡(攻擊領先者要有利可圖,而不只是洩憤)。
- 每個陣營的勝利條件都要是**自己能主動推進**的,不能只是「等別人失敗」。

### 5. 引擎、節奏與壓力時鐘(Uwe Rosenberg / Eurogame 傳統)
- 資源轉換鏈(引擎構築)是樂趣來源,但必須有**壓力時鐘**(回合上限、事件、稅)逼玩家在「擴張引擎」與「兌現勝利」之間取捨,否則人人縮在家裡種田。
- 遊戲要有**三幕劇弧線**:前期(建立引擎,選方向)→中期(互動衝突,路線碰撞)→後期(衝刺兌現,翻盤機會)。若每一輪玩起來都一樣,弧線壞了。
- 收斂性:遊戲必須**保證會結束**,且結束前 1~2 輪玩家要能感覺到「最後衝刺」。

### 6. 運氣、追趕與造王(Richard Garfield《Characteristics of Games》)
- **運氣是工具不是髒話**:運氣拉近新手與老手、製造故事;但運氣應該出現在「拿到什麼選項」(抽牌),不該出現在「決策的結果」(已確定的攻擊不該再擲骰)。
- **滾雪球 vs 橡皮筋**:領先者再加速(收入隨分數提高)會做出無聊的中盤;落後者補助太強(Mario Kart 化)會讓前期努力無意義。健康的結構:**領先者成為公敵(政治制衡)+ 落後者成本略低(經濟橡皮筋)**,兩者都溫和。
- **造王問題**:無法獲勝的玩家決定誰贏,是負面體驗的首因。解法:(a) 讓每位玩家到最後一刻都有自己的勝利路徑;(b) 把「協助他人」變成自己得分手段;(c) 隱藏資訊讓人無法確定誰真正領先。
- **淘汰與枯坐**:任何玩家不該在遊戲結束前失去所有影響力。被拆光的玩家要有重建的最低保障。

### 7. 體驗優先,機制服務體驗(MDA / Jesse Schell / Vlaada Chvátil)
- 先寫下「玩家應該感受到什麼」(Aesthetics),再推導動態(Dynamics),最後才選機制(Mechanics)。診斷問題時反向:這條機制產生了什麼動態?那個動態服務了哪種體驗?都答不出來就是贅肉。
- **複雜度預算**:玩家的腦容量有限,把預算花在「決策的深度」,不要花在「規則的記憶量」。例外、特例、once-per-turn 旗標都是高利貸——能合併就合併(lenticular design:新手看是簡單卡,老手看出組合技)。
- **下檔時間(downtime)**:不是你回合的時間也要有事做(看牌、規劃、談判)。任何讓單一玩家獨佔超過 90 秒的階段都要重做。

## 二、常見病灶診斷表

| 病灶 | 症狀 | 處方 |
|---|---|---|
| 滾雪球 | 中盤已定勝負,後段垃圾時間 | 收入與「自身建設」掛鉤而非「陣營總分」;領先公開化引導圍攻 |
| Mario Kart 化 | 前期領先無意義,大家擺爛到最後衝刺 | 補助只降成本不送分;追趕手段要花行動點 |
| 造王 | 輸家心情決定贏家 | 給每人到終局的私人勝利路徑;隱藏計分元素 |
| 必選項 | 某行動永遠是最優解 | 提高費用、加冷卻、或併入基本流程 |
| 假決策 | 某行動從沒人選 | 降費用、加附帶效益、或刪除 |
| 規則贅肉 | 教學超過 15 分鐘、玩家常忘規則 | 合併 once-per-turn 例外;特例改通則 |
| 枯坐 | 被打爆的玩家無事可做 | 保底收入/重建折扣;確保手牌永遠有可打的牌 |
| 終局拖沓 | 大家都看出結果還要再玩三輪 | 提前結束條件;末輪加倍計分製造懸念 |
| 純賭運 | 勝負取決於設置或抽牌而非決策 | 運氣前置(抽選項)而非後置(判結果);關鍵秘密改為玩家選擇 |

## 三、數值設計規範

1. **成本曲線**:同類資產的「費用 → 產出」要超線性成長(高階卡單位效率更高),但以「需要前置投資」(城市等級、科技樹)守門——獎勵長線規劃而非單純存錢。
2. **資源匯率**:多種資源間要有官方匯率錨點(本專案 2💰=1⚡/🛢️),所有卡片費用偏離錨點的幅度=該卡的策略傾斜度,偏離要是故意的。
3. **行動點經濟**:每回合 AP 是玩家最稀缺資源;任何「免 AP」的能力價值約等於 1/3 回合,定價要對得起這個重量。
4. **攻擊的期望值**:攻擊行動(費用+AP)對攻擊者的期望收益,應略低於同成本的建設(約 0.7~0.9 倍)——攻擊的真正報酬是「政治位置」,數值上偏弱才不會淪為互拆地獄。
5. **回合數×行動數=總決策量**:總決策量 / 遊戲分鐘數 ≥ 1 是底線;低於它就砍階段、併行動。
6. **改一個參數,跑一次模擬**:本專案有 `test/simulator.js --rules`,任何數值修改先 A/B 1000 局,看陣營勝率(目標:同人數下任一陣營勝率落在 40%~60%)、平均局長、與「終局方式分布」(達成勝利 vs 回合耗盡)。

## 四、規則修改審查清單

修改規則前逐項檢查:

- [ ] 這條規則服務哪個玩家幻想/情緒?(說不出來→砍)
- [ ] 新增了幾條「要記住的例外」?能否併入既有結構?
- [ ] 每個陣營在此規則下仍有可主動推進的勝利路徑?
- [ ] 對 3 人局與 8 人局分別的影響?(人數縮放 deckScale / 陣營人數差是本專案最大失衡源)
- [ ] 製造滾雪球還是橡皮筋?方向與力度對嗎?
- [ ] 是否違反記憶中已確認的 v2 語意?(混合牌庫、三資源、放棄權利制、飛機5倍油費、地盤加倍、一城一卡、12回合×事件卡——不可回退)
- [ ] 模擬器跑過了嗎?勝率/局長與基準線比較如何?
- [ ] 上帝模式/AI 內戰下這條規則是否仍可運作?(AI 策略六軸是否需要對應調整 `server/bot.js`)
